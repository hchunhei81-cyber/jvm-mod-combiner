Implemented in source · verify

Validate one-way state authority

Fabric remains the sole authoritative publisher for player and monster state. The DataBus checks the name attached during client registration, rejects protected types from other names, and keeps the connection open. Registration names are currently self-asserted, not authenticated.

  • Rust source rejects non-Fabric player_move and monster-state messages
  • Validate allowed registration names and address client impersonation
  • Rebuild/package Java Agent sources from bus_test/
  • Runtime-test rejection, no forwarding, and sender connection continuity
  • Verify Fabric delivery using the packaged Agent
  • Test reconnect and fresh authoritative state transmission
Early source prototype

Complete hostile-mob synchronization

bus_test/MonsterSync.java samples hostile Fabric mobs on the game thread at up to 5 Hz and emits initial/change messages. No NeoForge monster receiver is currently implemented.

  • Fabric-side mob discovery and state sampling by UUID
  • Detect and publish mob removals
  • Parse and apply monster messages in NeoForge
  • Test mirror lifecycle, world transitions, and reconnects
Following priorities

Stabilize, then expand

  • Stable remote-player identity, collision-safe IDs, and duplicate prevention
  • World/dimension changes, disconnect cleanup, and mirror recovery
  • Versioned protocol, message validation, sequence numbers, and stale-state rejection
  • Heartbeat, reconnect resynchronization, rate limits, and message-size limits
  • Refactor launcher dependency resolution and child-process management
  • Expand beyond player coordinates through incremental entity/state adapters
  • Investigate Mixin compatibility, cross-platform support, and advanced mod integrations
Scope guard: A successful loader launch or visual entity mirror does not mean arbitrary mods, inventories, combat, worlds, or game logic are synchronized.
